# Requirements

Test names below are planned acceptance tests, not claims that tests currently exist.

| ID | Requirement | Acceptance Criteria | Phases/Steps |
|----|-------------|---------------------|--------------|
| REQ-1 | Cancellation during pending macro work prevents subsequent dispatch and cleans indicator state. | Pending-indicator click/drag/scroll cancellation and cancellation immediately after completion send no pending action and emit no completed-step event. Pre-cancelled/no-indicator paths skip dispatch. Normal completion and reuse work. Pure composed lifecycle tests with fake dispatcher/view operations verify cancellation/completion races, hide/unsubscribe, teardown and reuse. Playback disposal initiates cancellation without synchronous drain; eventual operation-owned CTS/task cleanup and generation guards prevent stale completion mutating replacement state. test:MacroCancellationTests test:ClickIndicatorLifecycleTests test:MacroPlaybackTeardownTests | 1.1, 2.2 |
| REQ-2 | Document persisted RelativeTimeMs as recorder intervals without changing format or delay computation. | Timing guidance describes first-step delay from recording start and later intervals from previous timer resets, including drag-pair timing. Saved values, version and speed/floor behavior remain unchanged. file:docs/design-notes/macros.design.md#contains:inter-step test:Klikety.Tests.MacroPlayerTests.Play_SpeedModifier1_CorrectDelays | 1.2, 2.2 |
| REQ-3 | Native input produces typed outcomes and safe incomplete-send handling. | Failed movement suppresses dependent click. Every native send path returns/observes requested versus sent counts; partial button/modifier batches attempt release-only compensation once; failed cleanup is logged and carried in failure, with no action retry. Cover zero/partial/full sends for left/right/middle/double clicks, modifiers, scroll, drag phases and ClearStuckModifiers using fake transport/geometry/delay. Successful batch data/order/timing remain equivalent. test:MouseInputFailureTests test:MouseInputSuccessTests | 2.1, 2.2 |
| REQ-4 | Callers consume typed failures; macros stop and report failed input separately from cancellation. | A failed click/scroll/drag ends playback as InputFailed, sends no later macro steps and emits no progress for the failed step. Drag completion is awaited before the next saved interval starts; a drag-to-action test proves no overlap and unchanged saved intervals/speed/native phase delays. Handler returns to idle, closes progress and emits one error log for failed playback; no new tray notification. Non-macro action/recording/coordinator/scroll paths observe/log failure without unobserved tasks. Existing recording contents and successful overlay restoration remain unchanged. test:MacroInputFailureTests test:InputFailureCallerTests test:MacroDragSequencingTests | 2.1, 2.2 |
| REQ-5 | Reconcile keyboard-layout plan records while preserving history and local links. | Implement scripts/Test-KeyboardLayoutPlanRecords.ps1: filtered index asserts zero parse errors and one row for each retained canonical identity; supported Get-PlanState -Json for 000021 and the other retained ID asserts expected identity/path and full markers/progress/next-step fields; scoped Markdown link checks assert resolved assets and affected incoming references. Run against the repaired current tree and capture its actual exit/output under test:PlanIdentityRepairChecks. Preserve both records/content, no automatic archival. Unresolved ownership stops before mutation for operator decision. | 3.1 |

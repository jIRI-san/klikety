# Risks

| ID | Risk | Likelihood | Impact | Mitigation | Steps |

| RISK-1 | Cancellation/completion races or synchronous MacroHandler.Dispose deadlock the dispatcher; stale animation hides a later indicator. | Medium | High | Replace synchronous drain with nonblocking teardown and operation-owned cleanup; serialize terminal cleanup on dispatcher, cancel registrations/subscriptions, use generation guards; test pure lifecycle seam and teardown. | RISK-2 | Windows rejects release compensation or reports no useful last-error; extra release events affect physical keys. | Medium | High | Determine held synthetic inputs from sent prefix, capture primary diagnostics first, attempt release cleanup once, explicitly retain/log cleanup failure. No retry/bypass or guaranteed recovery claim. | 2.1, 2.2 |
| RISK-3 | Typed/async drag results broaden caller wiring or accidentally change recording/overlay behavior. | Medium | High | Trace every service caller, update all fakes/smoke compilation, test awaited completion and non-macro result observation. Completion-relative next-step scheduling intentionally removes drag overlap; test this selected behavior. Stop for operator decision if recording policy needs changing beyond observing failure. | 2.1, 2.2 |
| RISK-4 | Duplicate plan ownership or missing assets cannot be established; ID changes break historical references. | High | Medium | Compare current records and relevant git history, reserve a unique ID with existing helpers, inspect direct incoming links and retain history. No plugin reader bypass; stop before mutation if evidence leaves canonical ownership or compatibility ambiguous. | 3.1 |

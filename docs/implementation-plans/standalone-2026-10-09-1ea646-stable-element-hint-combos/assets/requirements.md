# Requirements

| ID | Requirement | Acceptance Criteria | Phases/Steps |
|----|-------------|---------------------|--------------|
| REQ-1 | Exact best-effort reuse | Consecutive scans with the same control identities and compatible level/layout keep combos despite changed batch order. Type/capability mismatches, changed groups and missing window identity do not borrow assignments. `test:ElementHintAssignmentTests` · `test:ProgressiveElementHintsSessionTests` | 1.1, 1.2, 2.1 |
| REQ-2 | Small bounded lifetime | One snapshot per window, retaining all allocated assignments including off-page entries and previously visited levels; window count follows cacheWindowCount, 0 disables reuse. Control/group counts respect existing caps. Worker retirement preserves memory; factory replacement drops it. No provider references or disk persistence. `test:ElementHintAssignmentTests` · `test:ElementHintsStateMachineTests` | 1.1, 2.1 |
| REQ-3 | Progressive publication and consistent input | Existing prefixes, selections and combos survive additions. Reserved holes reject keys; new controls use free slots/pages. Pin the active logical page even when an earlier page fills later. Matching levels retain their key scheme. Labels and key lookup use the same assignments. `test:ProgressiveElementHintsSessionTests` | 1.2, 2.1 |
| REQ-4 | Assignments are not actionable caches | Reused labels select only rediscovered current targets, using current tokens and unchanged validation. Empty/failure/partial/cancelled scans and late frames follow the snapshot rules; no old target is rendered or invoked. `test:ProgressiveElementHintsSessionTests` · `test:UiaWorkerSupervisorTests` | 1.2, 2.1 |
| REQ-5 | Document limited stability | Explain exact matching, holes, unchanged-group reuse and reset cases. Representative manual reopen evidence distinguishes static controls from rebuilt content. `file:docs/navigation.md#contains:best-effort` · `file:docs/design-notes/element-hints.design.md#contains:best-effort` | 2.1, 2.2 |

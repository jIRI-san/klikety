# Requirements

Named tests below are planned evidence, not claims of existing tests or completed verification.

| ID | Requirement | Acceptance Criteria | Phases/Steps |
|----|-------------|---------------------|--------------|
| REQ-1 | Overlay-local configurable help binding | Default OemQuestion matches unshifted and Shift presses, excludes unexpected Ctrl/Alt/Win, supports disabled/custom/Shift-required binding. Versioned migration preserves old configs/unknown fields, adds default help when collision-free or persists disabled help with warning; invalid explicit help bindings do not run. Modifier snapshots use separate hook flags and compatible event arguments, not mouse ActionModifiers. `test:HelpBindingTests` | 1.1, 3.1, 3.2 |
| REQ-2 | Reversible, paused help at any visible navigation state | Opening/closing preserves session identity, mode, cell/column/level, cursor/action point, origin, lock, scope, drag and recorder substate; unrelated overlay inputs cause no action or mutation; Escape closes help before navigation. `test:HelpOverlayCoordinatorTests` | 1.1, 2.1, 3.1, 3.2 |
| REQ-3 | Lifecycle and repeat safety | Opening requires visible overlay plus active session; activation-period presses ignored. Key-up removes debounce state/releases latches without toggling; held help/Escape does not repeat or leak into navigation. Idempotent cleanup clears flags/latches before hide, teardown, disposal or macro suspension; focus/display exit and activation toggle clear help. Existing system-key behavior retained. `test:HelpOverlayCoordinatorTests` | 1.1, 2.1, 3.1, 3.2 |
| REQ-4 | Effective non-navigation command map | Entries reflect Space default/override, mouse bindings, available/enabled modes/scope, display numbering, macro controls and slots, help/close; off-block custom keys included, disabled features omitted, unavailable commands muted/reasoned, navigation anchors unlabeled. `test:HelpBindingModelTests` | 1.2, 2.1, 3.1 |
| REQ-5 | Accurate macro/drag context and explicit exceptions | Slot/overwrite/start-from-cursor prompts and drag-target actions have contextual labels; named/empty slots accurate; opening help creates no step, recording clock continues; global shortcuts explicitly separate. Global picker from visible navigation uses existing hook-disable/suspend handoff, clears help before Show and preserves close/resume. Picker/playback windows have no help UI. `test:HelpBindingModelTests` `test:HelpOverlayCoordinatorTests` | 2.1, 3.1, 3.2 |
| REQ-6 | Split keyboard layout and readable themes | Two staggered halves around active-display center below midline, Space below gap, function keys above. Confirmed envelope: bounds/non-overlap at 800x600 DIP and larger with command text >=12 DIP; smaller viewports scroll within bounds. All long/custom entries discoverable; prompts/borders visible; dark/light category styles include text labels. `test:HelpKeyboardLayoutTests` | 2.2, 3.1, 3.2 |
| REQ-7 | Window-local DPI and layout-aware labels | Help uses active overlay DIP bounds, not app-scope/satellite coordinates. Existing keyboard-layout refresh rebuilds visible help; a viewport-change signal from SizeChanged/DpiChanged updates layout without mutating the session. Nonprintable keys have readable fallback names; slash/question glyphs not forced on unrelated layouts. `test:HelpKeyboardLayoutTests` `test:HelpKeyLabelTests` | 2.2, 3.1, 3.2 |
| REQ-8 | Related documentation updated | Delivered behavior/config documented in a new help note, root index, related notes and README; project-description synced if its summary changes. `file:docs/design-notes/keybinding-help.design.md#exists` `file:docs/design-notes/.design-notes.md#contains:keybinding-help` `file:README.md#contains:[Hh]elp` | 3.1 |
